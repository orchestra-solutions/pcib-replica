PCI PROXY SHIELD

Unabhängig von Ihrer Position in der Vertriebskette müssen Sie die Kreditkarteninformationen wochen- und manchmal monatelang speichern, um die Hotelreservierung zu garantieren. Daher müssen die Kreditkartendaten für die Dauer der Buchung aufbewahrt werden. Die Verwendung von PCI Proxy Shield vereinfacht nicht nur die Einhaltung der Vorschriften, sondern schützt auch die Kreditkartendaten der Kunden und die Marke des Unternehmens.

PCI Shield verwendet alle Anwendungen, Tools und APIs von PCI Bookings, um den spezifischen Anforderungen jedes einzelnen Akteurs in der Vertriebskette und seinem spezifischen Arbeitsablauf gerecht zu werden.

Tokenisierung

On-the-fly-Tokenisierung

Eliminiert mehrere Zahlungs-Gateway-Tokenisierungsschemata, die nicht miteinander kompatibel sind.

Pull-Tokenization-Anforderung (eingehende On-the-fly-HTTP-Anforderung)

Ermöglicht das Abfangen eingehender API-Anforderungen, die Erfassung von Kartendaten, die Verschlüsselung und die Speicherung auf sicheren PCI-Buchungs-Servern. Ein Token wird dann mit maskierten Kartendaten an den eCommerce-Server gesendet.

Tokenisierungs-Push (On-the-fly eingehende HTTP-Antworten)

Ermöglicht das Abfangen von zurückgegebenen API-Antworten und deren Weiterleitung an den API-Anforderer. Die erfassten Kartendaten werden verschlüsselt und auf sicheren PCI-Buchungs-Servern gespeichert, und ein Token wird mit maskierten Kartendaten an den eCommerce-Server gesendet.

Token-Ersatz – On-the-fly

Ermöglicht dem Vertriebskanal die Nutzung der Kartendaten in den API-Anforderungen an Dritte durch Bereitstellung eines Token. Vertriebskanäle können die Endkundenkarte in den API-Anforderungen an Dritte wie Zahlungsgateways oder Lieferanten (Hotels, Autovermietungen, Fluggesellschaften) verwenden, ohne dass die Kartendaten selbst offengelegt werden müssen.

Mehrere Kartenzahlungen mit einem Token

Die Lösung ermöglicht die Verwendung eines einzigen Token (Karte) für den Versand an mehrere Ziele, wodurch bis zu 90% der Kartenbearbeitungsgebühren eingespart werden können. Eine erfasste (und mit Token versehene) Karte kann für die Echtzeit-Zahlung an mehrere Parteien, wie z.B. alle mit einer Buchung verbundenen Anbieter, verwendet werden, d.h. Fluggesellschaften, Autovermieter, Autovermietungen, Zahlungsgateways usw. CVV-Details können in Anfragen enthalten sein. Erfasste Karten können auch Sicherheitscodedaten enthalten.

Kartenspeicher

Sichere Kartenspeicherung

Kartendaten können auf PCI-Buchungs-Servern unbegrenzt lange gespeichert werden. Dadurch wird den wiederkehrenden Kunden ein besserer Service geboten, indem schnelle Check-in- und Check-out-Prozesse ermöglicht werden.

Sichere Kartenspeicherkontrollen

Das Hinzufügen und Löschen von Karten im Speicher wird vom Kunden gesteuert. Dies ermöglicht eine flexible Politik der Karteneinbehaltung.

Abfrage der sicheren Kartenspeicherung

Möglichkeit, vorhandene Kartendaten, die auf PCI-Buchungs-Servern gespeichert sind, anhand benutzerdefinierter Referenzen abzufragen. Ermöglicht die einfache Auflistung von Karten, die mit einem bestimmten Endkunden in Verbindung stehen, und ermöglicht es dem Endkunden, eine bereits gespeicherte Karte auszuwählen, ohne dass er sensible Daten auf internen Systemen pflegen muss.

Kontrolle des Zugriffs Dritter auf Kartendaten

Erlauben Sie Drittanbietern wie Hotels, die bereits durch den Vertriebskanal erfassten Kartendaten zu verwenden. Dieselbe Karte kann mehrfach für verschiedene Buchungen bei verschiedenen Anbietern verwendet werden.
